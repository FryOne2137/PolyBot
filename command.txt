# 4a. Izolowany test jakości filtra z etapu 1. Obie strony używają dokładnie
# tego samego checkpointu i tych samych sparowanych map. Model A ma top 48 +
# 8 losowych + obowiązkowe ruchy taktyczne, a model B pełny policy prior.
# Wynik A bliski 0.50 oznacza brak istotnej utraty jakości; <0.45 sugeruje
# zwiększenie --mcts-top-actions. Ten test mierzy jakość, nie przyspieszenie.
python scripts/evaluate.py `
  --model-a models\teacher-structured-v1.pt `
  --model-b models\teacher-structured-v1.pt `
  --games 100 `
  --num-envs 128 `
  --mcts-threads 16 `
  --max-pending-leaves 8 `
  --belief-retries 4 `
  --simulations 64 `
  --particles 2 `
  --mcts-max-actions 1024 `
  --mcts-top-actions 48 `
  --mcts-random-actions 8 `
  --model-b-mcts-top-actions 0 `
  --model-b-mcts-random-actions 0 `
  --strategic-prior-weight 0.0 `
  --teacher-prior-weight 0.0 `
  --max-moves 500 `
  --seed 1500000007 `
  --device cuda

# 5. Liga z curriculum: najpierw szybka nauka przejmowania wiosek i innych
# widocznych celów bez MCTS, potem actor-critic bez MCTS i szybkie mecze
# surowej sieci przeciw całej populacji. MCTS uruchamia się jednocześnie we
# wszystkich etapach dopiero, gdy surowa sieć przejmuje miasta/wioski, kończy
# gry i nie cofa się przeciw żadnemu historycznemu modelowi. Szybkie etapy
# mogą wykorzystać do 5000 + 10000 kroków na rundę, ale dwie kolejne regresje
# kończą etap wcześniej na najlepszym bezpiecznym checkpointcie. Potem model
# przechodzi adaptacyjne szczeble 4,8,16,32,64; każdy ma bramkę i rollback.
# Checkpointy
# po promocji trafią
# do models\league\, pełna historia do models\league\league.sqlite3, a wykresy
# do runs\league\train\round_001, round_002 itd.

# seed self-play, a bramka osobny, nieużywany w treningu zestaw map. Wznów
# następny run od ostatniego champion-XXX.pt. Jeżeli nie było promocji, ale
# log podał "challenger retained", zachowaj tego samego --champion-in i dopisz
# --challenger-in models\league\champion-challenger-XXX.pt.
