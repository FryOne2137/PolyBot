# 5. Liga z curriculum. Pierwszy model może korzystać z teachera oraz objectives:
# krótkich, wielokrokowych rolloutów, które przekazują sygnał wioski/miasta do
# ruchów prowadzących do celu. Po pierwszym awansie teacher i actor-critic są
# pomijane, ale działa mały refresh objectives; champion dostaje 65% gier, a
# populacja trenuje 6000-12000 kroków przeciw championowi i historii.
# Tryb auto zaczyna od płaskiej policy. Dopiero po dwóch kolejnych udanych
# sparowanych probe'ach przy 32 symulacjach przechodzi do zamrożonych generacji
# MCTS; wcześniejsze rundy nadal promuje wyłącznie raw policy.
# search@32 musi ściśle pobić raw policy na tych samych mapach.
# Dwa kolejne udane probe'y zapisują status MCTS-ready. Od następnej rundy jest
# wykonywane frozen MCTS collection → fixed replay → aktualizacja challengera;
# nieudany rung wraca do poprzedniego MCTS-ready championa. Dlatego komenda ma
# co najmniej 3 rundy: dwie mogą potwierdzić gotowość, a trzecia ją wykorzystać.
# Bramka populacji priorytetowo traktuje wynik gry; przejęcia i completion są
# tie-breakerami, a historyczny floor pozostaje twardym zabezpieczeniem. PPO
# używa wyniku całej partii dla value/PPG, gamma=1, wygaszanego shaping i EMA.
# Główna linia jest pojedyncza i kontynuowana między rundami. Generacje MCTS są
# uruchamiane dopiero automatycznie po probe'ach, nigdy na słabym backbone'u.
# Checkpointy
# po promocji trafią
# do models\league\, pełna historia do models\league\league.sqlite3, a wykresy
# do runs\league\train\round_001, round_002 itd.
# Stały --seed jest bazą wielu map, nie jednej mapy. Każda runda ma odległy
# seed self-play, a bramka osobny, nieużywany w treningu zestaw map.
# Płaskie bramki tej komendy automatycznie używają dwóch natywnych batchy
# VectorGameEnv, buforów reset_into/step_into i pamięci pinned na CUDA. Nie
# potrzeba osobnej flagi; --num-threads ustawia również workery tych bramek.
# Wariant recovery dla championa, którego raw policy/value/belief są jeszcze
# za słabe jako prior dla MCTS. Każda runda kontynuuje bezpiecznego challengera
# (jedna gałąź), a --refresh-promoted-curriculum przywraca teacher/objectives/
# actor-critic także dla promowanego championa. Destylacja MCTS uruchamia się
# dopiero po sparowanym probe: search musi pobić raw policy na tych samych
# mapach i osiągnąć --mcts-probe-score. W przeciwnym razie jest pomijana.
# Krytyczne pozycje są trwałe w models\league\mcts-reanalyse.pkl; w kolejnych
# rundach osiem z nich jest odtwarzanych z seeda i analizowanych ponownie przez
# aktualny MCTS. Search używa co najmniej 32 najlepszych + 8 losowych legalnych
# akcji; --mcts-min-prior-mass 0.85 rozszerza tę pulę, gdy prior jest płaski.
# Obowiązkowe ruchy taktyczne pozostają dostępne, a bramka raw policy nadal
# cofa destylację, jeśli ta nie pomaga.
# --direct-gate-max-moves jest konieczny, bo ten etap ma osobny limit ruchów
